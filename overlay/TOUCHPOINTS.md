# Touchpoints

Every file outside `overlay/` that differs from `upstream/master`, and why.
This file is the merge-cost ledger of the fork: each entry is a place that can
conflict on a sync. Keep it short and keep it honest.

Regenerate the real list with `overlay/scripts/overlay-diff.sh`; it fails if a
changed upstream file has no entry here.

Template for new entries:

```
### `path/to/file`

- What: one line describing the edit.
- Why here: why it could not be done from overlay/, hooks, or config.
- Retire when: the upstream change that would let us delete this.
```

## spaces (`overlay/herdr-spaces`)

Codex-style spaces: a named group of folders (plus optional emoji) persisted in
`<config dir>/spaces.json`, used to group the sidebar and to seed workspace and
worktree creation. All logic lives in the `herdr-spaces` crate; the entries
below are the call sites that reach it.

Two design choices worth recording, both chosen for the smaller upstream diff:

- Sidebar headers are real header rows, not a label prefix on the first card.
  The header row is reserved by the same three functions that size and place
  cards (`workspace_list_visible_count`, `workspace_list_bottom_start`,
  `compute_workspace_list_areas`), so scroll math, card rects, mouse
  hit-testing, and drag slots stay consistent without touching
  `WorkspaceListEntry` or the card geometry itself. Headers mark each run of
  consecutive workspaces that share a space; workspaces are **not** reordered,
  because entry order is also the model order used by drag-to-reorder
  (`workspace_move_block_params`).
- The picker is a `Mode` variant plus one `AppState` field, rather than a new
  parallel modal system. Modal line composition happens in the crate
  (`herdr_spaces::view`), so the ratatui call site stays a tone-to-style map.

### `Cargo.toml`

- What: declare a cargo workspace with `overlay/herdr-spaces` as a member and
  `default-members = ["."]`, and add the path dependency.
- Why here: a crate has to be reachable from the root manifest; nothing else
  can add a dependency to the herdr package.
- Retire when: herdr grows a plugin API that can own UI modes and sidebar
  rendering out-of-tree.

### `Cargo.lock`

- What: lock entry for `herdr-spaces` and its `unicode-width` dependency
  (already an herdr dependency, so no new third-party crate enters the tree).
- Why here: generated by cargo from the manifest change above.
- Retire when: the manifest touchpoint goes away.

### `src/app/state.rs`

- What: one `AppState` field (`spaces`, holding the loaded list and the open
  picker) and one `Mode::SpacePicker` variant.
- Why here: `AppState` and `Mode` are the only state containers the TUI reads,
  and both are defined here.
- Retire when: upstream exposes registrable modes or client-side state slots.

### `src/app/mod.rs`

- What: load `spaces.json` into the new field at startup, and route
  `Mode::SpacePicker` keys in the headless server key handler.
- Why here: both the `AppState` literal and the headless key match are here and
  are exhaustive over `Mode`. Also holds the `App::next_spaces_reload_poll`
  deadline field and its `SPACES_RELOAD_POLL_INTERVAL` constant, alongside
  their siblings `next_resize_poll`/`RESIZE_POLL_INTERVAL`; the poll itself
  lives in `runtime.rs`.
- Retire when: same as `src/app/state.rs`.

### `src/app/creation.rs`

- What: `begin_tui_workspace_create` opens the space picker when spaces.json is
  non-empty; re-entry from the picker itself falls through to upstream. Calls
  `spaces.maybe_reload()` first, so a hand-edit is picked up before deciding
  empty-vs-picker.
- Why here: this is the single funnel for prefix+m and the sidebar new button.
- Retire when: upstream offers a hook for "user asked for a new workspace".

### `src/app/runtime.rs`

- What: `App::reload_spaces`, a coarse (2s) poll that calls
  `herdr_spaces::SpacesState::maybe_reload` and leaves `Mode::SpacePicker` if
  the reload just closed an open picker out from under it. Called from
  `handle_scheduled_tasks`, and `next_spaces_reload_poll` is one of the
  deadlines `next_loop_deadline` reports so the event loop wakes up for it.
  `handle_scheduled_tasks_headless` in `src/server/headless.rs` calls the
  same `reload_spaces` method on its own due-check.
- Why here: this is the app's scheduled-task loop; `herdr-spaces` owns no
  event loop and must not depend on `App`/`Mode`.
- Retire when: same as `src/app/state.rs`.

### `src/server/headless.rs`

- What: `handle_scheduled_tasks_headless` calls `App::reload_spaces` on the
  same coarse poll as the interactive loop. This is the path that matters in
  practice: the app runs here, in the long-running server process, not in
  the thin per-client renderer.
- Why here: the headless server has its own scheduled-task function (it
  skips resize polling, which has no meaning without a local terminal) and
  therefore its own copy of the due-check; `App::reload_spaces` stays
  `pub(crate)` in `src/app/runtime.rs` so both loops share one code path.
- Retire when: same as `src/app/state.rs`.

### `src/app/input/mod.rs`

- What: one match arm routing `Mode::SpacePicker` key events.
- Why here: the TUI key dispatch match is exhaustive over `Mode`.
- Retire when: same as `src/app/state.rs`.

### `src/app/input/modal.rs`

- What: `handle_space_picker_key` (translates keys, runs the crate state
  machine, and executes the returned action) plus the key translation helper.
- Why here: the action side needs `App` (workspace create, worktree dialog),
  which the crate must not depend on.
- Retire when: same as `src/app/state.rs`.

### `src/app/worktrees.rs`

- What: `open_new_linked_worktree_dialog_for_cwd`, seeding the existing
  new-worktree dialog from a space folder that may have no open workspace; and
  `submit_worktree_create_via_api` now sends `cwd` instead of `workspace_id`
  when the dialog was seeded that way.
- Why here: `WorktreeCreateState` and the submit path are herdr-internal. The
  API already accepts a raw cwd (`resolve_worktree_source`), so this only
  chooses which field to send.
- Retire when: upstream can open the worktree dialog from a path.

### `src/ui.rs`

- What: import plus one match arm rendering the picker overlay.
- Why here: the overlay render match is exhaustive over `Mode`.
- Retire when: same as `src/app/state.rs`.

### `src/ui/dialogs.rs`

- What: the picker modal renderer, its geometry helpers, and the tone-to-style
  map (also used by the sidebar header).
- Why here: rendering needs ratatui, the palette, and `AppState`.
- Retire when: same as `src/app/state.rs`.

### `src/ui/sidebar.rs`

- What: space header rows in the workspace list: a header row reserved in the
  three list-math functions, the header drawn in `render_workspace_list`, and
  small helpers that resolve a workspace to a space via the crate.
- Why here: the workspace list geometry and render loop are private to this
  module, and card rects must stay in sync with the reserved rows.
- Retire when: upstream supports grouped sidebar sections.
